# 快递整理

一款手机优先、完全本地运行的快递截图整理 PWA。截图通过 Tesseract.js 在浏览器内识别，不上传图片；包裹资料和压缩后的原始截图保存在本机 IndexedDB。

“物流跟踪”保存运输中的包裹，“取件管理”展示已经识别出取件码或驿站的包裹，并提示还有多少在途包裹等待添加到站截图。相同快递单号的新截图会自动合并到原记录，多张阶段截图使用同一识别颜色。已签收包裹收进页面底部的折叠区。

取件地点分组优先使用道路门牌号和校园地标形成本地点位指纹，可合并“北四驿站/北四店”“668号中通/668店”等同址别名。卡片可右滑标记取件完成，点开可查看全部本机截图。相册支持一次选择多张图片：应用逐张 OCR 后按清洗后的快递单号自动拆成多个订单，相同单号的阶段截图才会合并。

上传前可以为整批截图指定购买平台，支持淘宝、京东、拼多多、抖音、小红书、唯品会、得物和“其他”自定义平台；未指定时仍由本地 OCR 谨慎识别，识别不可靠则保持“待确认”。

包裹详情页可继续上传最新的到站截图。应用会把新图合并到原包裹，利用新识别结果校准快递单号并更新取件码、站点；即使新截图没有取件码，也会将该包裹放入待取件列表。

## 本地运行

```bash
pnpm install
pnpm dev
```

打开终端显示的本地地址。生产构建与测试：

```bash
pnpm test
pnpm build
pnpm preview
```

首次 OCR 会联网下载开源中文识别模型，之后模型会被浏览器缓存。确认添加后，应用只保留压缩后的本机副本，并立即释放上传时的原图内存；不会把图片发送到云端。

## 免费部署到 GitHub Pages

1. 在 GitHub 新建一个公开仓库。
2. 把本项目提交并推送到仓库的 `main` 分支。
3. 打开仓库的 **Settings → Pages**，将 **Source** 设为 **GitHub Actions**。
4. 推送后等待“部署到 GitHub Pages”工作流完成。
5. 打开 Pages 地址。在 iPhone Safari 中点“分享”→“添加到主屏幕”。

项目使用相对路径和 Hash 路由，无需修改仓库名或 `base` 配置。

## 安装与分享

PWA 不需要从应用商店下载。部署完成后，把 GitHub Pages 的 HTTPS 地址发给其他人即可；每个人的数据和截图都只保存在自己的设备中，互相不可见。

### iPhone / iPad

1. 必须使用 Safari 打开 GitHub Pages 地址。
2. 点击 Safari 底部的“分享”按钮。
3. 向下找到“添加到主屏幕”。
4. 点击右上角“添加”，以后从桌面上的“快递整理”图标启动。

### 安卓手机

1. 使用 Chrome 打开 GitHub Pages 地址。
2. 点击右上角菜单，选择“安装应用”或“添加到主屏幕”。
3. 确认安装，之后从桌面图标启动。

### Windows / macOS

使用 Chrome 或 Edge 打开 GitHub Pages 地址，点击地址栏右侧的安装图标并确认。

首次打开和首次 OCR 需要联网下载应用文件及免费识别模型。加载成功后，应用界面可以离线打开；识别模型是否可离线复用取决于浏览器缓存是否仍被保留。更新程序后，重新打开应用会自动获取新版本。

## 隐私与数据

- 无后端、无账号、无数据库服务器、无付费 API。
- 不提供实时物流查询；官方查询会先复制单号，再打开快递公司官网供粘贴。
- 导出 JSON 用于本地备份（包括本机截图）；导入会按记录 ID 合并，已有同 ID 记录会更新。
- OCR 会自动填写能可靠识别的购买平台、快递公司、快递单号、收货站点、收货地址、取件码、商品名称和物流状态；无法确认的字段保持为空或“待确认”，由用户补充。
